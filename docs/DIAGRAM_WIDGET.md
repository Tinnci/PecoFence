# 图表组件（Mermaid）

provider 为 `pecofence.diagram`，配置版本 1，格式为 `{ "source": "..." }`，正文最多 16384 个 UTF-16 单位。托盘与栅栏右键的“新建小组件 › 图表”创建 560×400 DIP 的组件，并立即打开多行编辑框，预填一个可修改的示例。

## 原生实现

参考 [Pele](https://github.com/obsidianmd/pele)（MIT）的思路：Mermaid 文本直接绘制为主题化矢量图。PecoFence 不嵌入 JavaScript 引擎，也不依赖 Node.js、浏览器或 SVG 渲染器。**只借鉴思路，不复制 Pele 的代码或数据表**（关键字表、字符宽度表、测试用例等均自行编写）。`diagram.rs` 把结果映射为场景节点：节点为圆角矩形和文字，连线、箭头、菱形和子图边框用场景节点的 `path` 折线绘制。因此图表随 DPI 保持清晰，使用暖纸色方案，节点文字和子图标题可被 UIA 读取。

`crates/plugin-widgets/src/mermaid/` 按 Pele 的流水线分段：

- `mod.rs`：**预处理**（`preprocess`：front matter 只读 `title:`，去掉注释行和空行，保留原始行号；与 Mermaid 一致，只有首个非空白文字为 `%%` 的行才是注释（含 `%%{init}%%`），行内的 `%%` 是普通文字）→ **识别**（`detect`：首条语句的第一个关键字）→ **注册表**（`TYPES`：每种图表类型 = 关键字列表 + `parse` 函数）。已知但未实现的类型在 `UNSUPPORTED` 中，报“暂不支持”。这里还有语句切分 `statements`（小型分词：`;` 只在引号、`[]`/`()`/`{}`、`|…|` 连线标签和 `#…;` 实体码之外才结束语句）、实体码解码 `decode_entities`（`#59;`、`#quot;`、十进制 `#NNN;` 及少量命名实体，未知的原样保留）、文字测量（见下）与共享的诊断类型 `Diagnostic`。
- 解析结果为 `Parsed { diagram, warnings }`：致命问题作为 `Err(Diagnostic)`（严重度 `Error`），其余问题进入 `warnings`，各带行号、原因与严重度（`Warning`：结果可能与 Mermaid 不同；`Info`：只影响样式，如 `style`、`classDef`、`axisFormat`）。
- `flowchart.rs`：流程图解析与分层布局。
- `gantt.rs`：甘特图解析（逐行绘制，无独立布局）。

新增一种图表类型：新建模块，实现 `fn parse(&Source, &mut Vec<Diagnostic>) -> Result<Diagram, Diagnostic>`，在 `Diagram` 枚举加一个分支，在 `TYPES` 加一项，再在 `diagram.rs` 加绘制函数。

评估过 `mermaid-rs-renderer`（MIT，约 2.2 万行，依赖 regex、json5，并通过 fontdb 扫描系统字体测量文字）和 `merman`。为控制 6.5 MiB EXE 上限和启动开销，未引入。

## 支持范围

- `flowchart` / `graph`：方向 LR、RL、TB/TD、BT；节点形状 `[ ]`、`( )`、`([ ])`、`(( ))`、`{ }`（`[[ ]]`、`[( )]`、`{{ }}`、`> ]` 按近似形状绘制）；连线 `-->`、`---`、`-.->`、`==>`、`--x`/`--o`（按箭头绘制）、`<-->`；标签 `-->|文字|`（可加引号，如 `-->|"a | b"|`）和 `-- 文字 -->`；节点标签可加引号（`A["含 ] 的文字"]`）；标签中可含 `;`、`%%` 与实体码（`#59;`、`#quot;`、`#9829;`）；`A & B --> C`；链式 `A --> B --> C`；`;` 分隔（含 `graph TD;A-->B;` 这种写在首行的语句）；`%%` 注释行；front matter `title:`；`subgraph id [标题]` / `subgraph "标题"` / `subgraph 标题` … `end`（可嵌套，节点归属它首次出现时所在的最内层子图）。`style`、`classDef`、`class`、`linkStyle`、`click`、`direction` 行不参与绘制，记为 `Info` 级提示（不显示横幅）。
- `gantt`：`title`、`dateFormat YYYY-MM-DD`、`section`、任务 `名称 : [done|active|crit|milestone,] [id,] [开始,] 结束`；开始可为日期或 `after id…`，结束可为日期或 `Nd`/`Nw`。
  - `excludes` 支持 `weekends`、星期名（`sunday` 等）和 `YYYY-MM-DD` 日期，可用空格或逗号分隔，且与 Mermaid 一样对全部任务生效（无论写在第几行）。`weekend friday` / `weekend saturday` 选择周末为周五六或周六日。按 Mermaid 的规则：以时长给出的任务只计入开放日，结束日顺延；后续任务（`after` 或省略开始）从下一个开放日开始；显式写出的结束日期不顺延。若排除了一周的每一天，按星期排除的规则会被忽略并给出提示。
  - 未实现的排期指令 `includes`、`todayMarker`、`tickInterval`、`weekday`、`inclusiveEndDates`，以及非 `YYYY-MM-DD` 的 `dateFormat`（日期仍按 `YYYY-MM-DD` 读取），产生 `Warning` 级提示；无法识别的 `excludes` 项同样提示。`axisFormat`、`topAxis`、`displayMode` 为 `Info`。
- 其他图表类型显示“暂不支持”。上限：200 个节点（子图数同样不超过 200）、400 条连线、120 个任务；`A & B & C --> D & E` 这类分组按笛卡尔积展开，展开后同样受 400 条上限约束。

## 布局与呈现

流程图采用分层（Sugiyama 式）布局：

1. 最长路径分层，DFS 回边不参与分层；回边按反向连线布局后再倒转绘制，因此不再需要图外的回边通道。
2. 节点占偶数槽，连线标签占相邻节点层之间的奇数槽（Pele 的“标签节点”思路）：带标签的连线在其跨度中间的空隙里得到一个与标签等大的虚拟顶点，为标签预留空间，标签不会压在节点上。跨越多层的连线在途经的每个有内容的层上都有虚拟顶点，所以长连线绕开中间节点，不会穿过节点框。没有标签的层间空隙保持 56 DIP；有标签时两侧各 28 DIP，中间是标签尺寸。
3. 六轮重心排序（含虚拟顶点）。排序键是“子图路径”：外层子图的键在前、顶点自身的重心在后；子图的键取其全部顶点（跨所有层）的平均位置，因此每一层级的子图在每层内都保持相邻，且各层中子图的先后顺序一致。排序结束后再用固定的键统一排一遍，消除各轮键值漂移造成的层间顺序不一致。连线的虚拟顶点属于两端所在的最内层公共子图，所以跨子图的连线及其标签不会落进任一子图内部。
4. 各层沿公共轴居中，使并行分支对称；连线为正交折线，只在层与层之间的空隙里拐弯。
5. 端口与走线轨道（Pele 的目标 1 和 4），按容量分配空间：同一节点同一侧的多个连线端点沿该侧分开排列，按连线去向排序以免交叉；每个端点至少占 `PORT_GAP` = 8 DIP，放不下时节点沿横穿流向的方向长大（扣除各形状的端点边距；圆形保持正圆，菱形按斜边可用的一半计算）。菱形和圆形的端点落在轮廓上（菱形即顶点两侧的斜边）。每个层间空隙里的拐弯各占一条轨道，轨道间距至少 `TRACK_GAP` = 8 DIP，空隙按轨道数加宽，并扣除两侧子图边框所需的空间（轨道只用中间的空余部分）。离开某一横向位置的连线先于到达该位置附近的连线拐弯（拓扑排序，保留原有的不交叉顺序）；两条连线在相邻层之间以几乎相同的位置互换时，其中一个虚拟顶点横向挪开一条轨道的宽度（挪动前检查同层邻居与子图边界），否则无论谁先拐都会并行重叠一段。不做干线合并：扇出时目标那一列总比源节点高得多，放大的节点仍成比例，而合并会违反“端点分开、线段不重叠”的不变量。
6. 子图作为容器参与布局：自内而外打包，每个子图在它跨越的所有层中占用同一段横向区间（区间宽度 = 内容宽度 + 两侧 `CLUSTER_PAD`，横向流向时另加顶部标题条），其直接成员与子容器在区间内排布；外层只把自由顶点放进各子图区间之间的空隙，并为每一层所需的空隙留足宽度。子图即使在某层没有自己的顶点（只有外部连线穿过），也在该层保留区间。沿流向，子图首层之前与末层之后的空隙按嵌套层数留出内边距，纵向流向时再留出标题条（自下而上时标题条在末层之后，仍位于图上方）。边框直接由区间和层跨度得出，因此不会圈进外部节点、外部连线的标签或其他子图的边框，有成员的子图一律绘制边框。

图按舞台大小缩放，文字与几何使用同一个比例：布局在自身单位（DIP）中完成，节点框、标签框、圆角、箭头和字号一起乘以缩放比例，因此标签与其预留框的比例在任何舞台尺寸下都不变（不再有字号下限，旧实现在 40% 时文字约为框的 1.7 倍）。比例不超过 100%（不放大），也不低于 `MIN_SCALE` = 70%，此时 13 DIP 的节点标签为 9.1 DIP。仍放不下时不再缩小，而是按 70% 绘制（放不下的方向从左或上起排），并在舞台边缘裁剪：被切到的连线和边框在边缘截断，被切到的节点保留轮廓与 UIA 名称但不画文字，完全在外的部分不画；舞台右下角显示“图表过大 · 按 70% 显示，其余已裁剪”的状态胶囊（UIA 角色 status）。暂不支持平移。甘特图按任务行绘制条形，跨度不超过 12 周时按 ISO 周显示刻度，否则按月；`section` 标题单独占一行，位于该分组第一个任务之上；“今天”以赤陶色竖线标出；关键任务为赤陶色，已完成为浅色，进行中为强调浅底，里程碑为菱形。

源码有误时页眉以警示色提示，舞台保留上次成功的图（淡化显示），底部横幅给出行号、原因和该行内容（UIA 角色为 alert）。解析成功但有 `Warning` 级提示时，图照常（不淡化）绘制在缩小的区域里，下方同样的横幅显示第一条提示及“另有 N 条提示”，UIA 角色为 status；只有 `Info` 时不显示横幅。整个舞台点击即编辑源码；支持撤销上一步。修改后图表淡入（250 ms，关闭“动画效果”时不播放）。高度低于 120 DIP 时显示单行胶囊摘要。

## 文字测量

布局通过 `TextMeasure` trait 取得文字宽度，可注入：

- 组件运行时使用宿主的 `RenderService::measure`。应用端（`panel_manager.rs` 的 `HostRender`）现在用 `pecofence_render::TextFormatCache::measure` 走 DirectWrite，字体为暖纸正文字体（`FontRole::PaperBody`，即捆绑的 Noto Sans SC，缺失时回退 Segoe UI Variable）。测量只在源码变化、重新布局时进行，结果随布局缓存，不在每帧调用；服务不可用时回退到估算。
- 测试和回退使用确定性的 `Estimate`：ASCII 约 0.56 em（大写 0.64 em）；中日韩、谚文和全角字符 1 em；组合附加符号、控制字符和零宽字符（ZWSP、ZWJ、变体选择符、BOM 等）为 0；其他字符 0.6 em。

节点标签超过 192 DIP 时自动换行（先在空格处断，再在中日韩字符之间断，单个词过长才在词内断），节点随行数增高，常见长度的标签不再被裁剪；连线标签同理，最宽 160 DIP。甘特图任务名列宽在布局时测量一次。

## 取舍

从 Pele 借鉴并已实现：预处理 → 识别 → 注册表 → 解析 → 布局 → 绘制的流水线；可注入的确定性文字测量；分层布局中的虚拟顶点与标签节点；复合（子图）边框的简化版；以布局不变量为主的测试。从 Mermaid 的流程图解析器规格（`flow-text.spec.js` 等，MIT）改编了一组关于引号与标签的表格用例（见 `mermaid/mod.rs` 中的注释），未复制 Pele 的代码。

刻意未做：Pele 其余的连线走线目标（如减少拐点；端口与轨道的容量分配已实现）、干线合并、其余图表类型。子图的复合布局为自行实现的区间打包（见上文第 6 步），不同于 Pele 的实现。

## 验证与限制

`cargo test -p pecofence-plugin-widgets` 覆盖：流水线（front matter 与注释行、行内 `%%` 保留、关键字识别、暂不支持的类型与行号）；语句切分与实体码；改编自 Mermaid 规格的引号与标签表格用例；甘特图 `excludes weekends`、`weekend friday`、星期与日期排除，以及各类被忽略指令的提示与严重度；文字测量（零宽与组合符号、宽字符、换行规则）；解析（形状、链、分组、标签、子图嵌套、错误行号、甘特依赖、分组展开不超过连线上限）；布局不变量——在四个方向、带标签、长连线、环、自环、子图和若干伪随机图上检查：节点框互不重叠，连线线段不穿过任何节点框且均为水平或竖直，同一节点上不同连线的端点相距至少 8 DIP（扇出 3–20 条、四个方向），任意两条连线的线段不共线重叠，平行线段相距至少半条轨道（4 DIP），标签不压节点且位于自身连线上，有成员的子图一律有边框、边框包住成员且不圈进外部节点、外部连线的标签或不相干的子图边框（含嵌套子图的随机图，四个方向），同一输入布局结果完全一致；场景（在多种舞台尺寸下每个标签的字号与框高之比与未缩放时相差不超过 5% 且不低于最小字号、过大的图按 70% 裁剪并显示状态胶囊且所有内容留在舞台内、警告横幅位于图下方且不淡化图、节点在舞台内、箭头数量、直线与今天线确实绘制、子图边框与标题、标签不压节点、错误横幅、空白与胶囊状态）。

像素快照 `diagram_snapshots_hold_their_layout`（`tests/snapshots/`）另含裁剪的流程图与带警告横幅的甘特图。

限制：尚未在 Windows 设备上做视觉、IME、屏幕阅读器验收；放不下的图只裁剪、不能平移；自环的标签不预留空间；虚线连线以浅色细线表示。在一次 1440 张随机图（12–40 个节点、带与不带嵌套子图、四个方向）的压力测试中，约 8% 仍有两条连线并行靠近或共线一段（多为三条连线互换、或互换时没有挪动空间的情况；同样的检查在改动前的实现上为 94%）；压力测试未纳入常规测试。
