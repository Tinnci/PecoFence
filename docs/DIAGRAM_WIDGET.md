# 图表组件（Mermaid）

provider 为 `pecofence.diagram`，配置版本 1，格式为 `{ "source": "..." }`，正文最多 16384 个 UTF-16 单位。托盘与栅栏右键的“新建小组件 › 图表”创建 560×400 DIP 的组件，并立即打开多行编辑框，预填一个可修改的示例。

## 原生实现

参考 [Pele](https://github.com/obsidianmd/pele)（MIT）的思路：Mermaid 文本直接绘制为主题化矢量图。PecoFence 不嵌入 JavaScript 引擎，也不依赖 Node.js、浏览器或 SVG 渲染器。**只借鉴思路，不复制 Pele 的代码或数据表**（关键字表、字符宽度表、测试用例等均自行编写）。`diagram.rs` 把结果映射为场景节点：节点为圆角矩形和文字，连线、箭头、菱形和子图边框用场景节点的 `path` 折线绘制。因此图表随 DPI 保持清晰，使用暖纸色方案，节点文字和子图标题可被 UIA 读取。

`crates/plugin-widgets/src/mermaid/` 按 Pele 的流水线分段：

- `mod.rs`：**预处理**（`preprocess`：front matter 只读 `title:`，去掉 `%%` 注释和空行，保留原始行号）→ **识别**（`detect`：首条语句的第一个关键字）→ **注册表**（`TYPES`：每种图表类型 = 关键字列表 + `parse` 函数）。已知但未实现的类型在 `UNSUPPORTED` 中，报“暂不支持”。这里还有文字测量（见下）与共享的错误类型。
- `flowchart.rs`：流程图解析与分层布局。
- `gantt.rs`：甘特图解析（逐行绘制，无独立布局）。

新增一种图表类型：新建模块，实现 `fn parse(&Source) -> Result<Diagram, ParseError>`，在 `Diagram` 枚举加一个分支，在 `TYPES` 加一项，再在 `diagram.rs` 加绘制函数。

评估过 `mermaid-rs-renderer`（MIT，约 2.2 万行，依赖 regex、json5，并通过 fontdb 扫描系统字体测量文字）和 `merman`。为控制 6.5 MiB EXE 上限和启动开销，未引入。

## 支持范围

- `flowchart` / `graph`：方向 LR、RL、TB/TD、BT；节点形状 `[ ]`、`( )`、`([ ])`、`(( ))`、`{ }`（`[[ ]]`、`[( )]`、`{{ }}`、`> ]` 按近似形状绘制）；连线 `-->`、`---`、`-.->`、`==>`、`--x`/`--o`（按箭头绘制）、`<-->`；标签 `-->|文字|` 和 `-- 文字 -->`；`A & B --> C`；链式 `A --> B --> C`；`;` 分隔；`%%` 注释；front matter `title:`；`subgraph id [标题]` / `subgraph "标题"` / `subgraph 标题` … `end`（可嵌套，节点归属它首次出现时所在的最内层子图）。`style`、`classDef`、`class`、`linkStyle`、`click`、`direction` 行会被忽略。
- `gantt`：`title`、`dateFormat YYYY-MM-DD`、`section`、任务 `名称 : [done|active|crit|milestone,] [id,] [开始,] 结束`；开始可为日期或 `after id…`，结束可为日期或 `Nd`/`Nw`。`axisFormat`、`excludes` 等行被忽略。
- 其他图表类型显示“暂不支持”。上限：200 个节点（子图数同样不超过 200）、400 条连线、120 个任务；`A & B & C --> D & E` 这类分组按笛卡尔积展开，展开后同样受 400 条上限约束。

## 布局与呈现

流程图采用分层（Sugiyama 式）布局：

1. 最长路径分层，DFS 回边不参与分层；回边按反向连线布局后再倒转绘制，因此不再需要图外的回边通道。
2. 节点占偶数槽，连线标签占相邻节点层之间的奇数槽（Pele 的“标签节点”思路）：带标签的连线在其跨度中间的空隙里得到一个与标签等大的虚拟顶点，为标签预留空间，标签不会压在节点上。跨越多层的连线在途经的每个有内容的层上都有虚拟顶点，所以长连线绕开中间节点，不会穿过节点框。没有标签的层间空隙保持 56 DIP；有标签时两侧各 28 DIP，中间是标签尺寸。
3. 六轮重心排序（含虚拟顶点）；同一顶层子图的成员在每层内保持相邻，不同子图的相邻顶点之间额外留出边框与标题的空间。
4. 各层沿公共轴居中，使并行分支对称；连线为正交折线，只在层与层之间的空隙里拐弯。
5. 端口与走线轨道（Pele 的目标 1 和 4）：同一节点同一侧的多个连线端点沿该侧分开排列，按连线去向排序以免交叉；菱形和圆形的端点落在轮廓上（菱形即顶点两侧的斜边）。每个层间空隙里的拐弯各占一条轨道，向下与向上的连线分别按起点排序，因此两条连线不会共用端点，也不会重叠成一条线。
6. 子图边框包住全部成员（嵌套子图逐层加宽内边距），顶部留标题条。没有完整的复合布局，所以当边框会圈进外部节点、外部连线的标签或不相干的边框时，该边框不画（成员照常布局），而不是画出误导性的分组。

图按舞台大小缩放（不放大，最小 40%，再大则裁剪）。甘特图按任务行绘制条形，跨度不超过 12 周时按 ISO 周显示刻度，否则按月；`section` 标题单独占一行，位于该分组第一个任务之上；“今天”以赤陶色竖线标出；关键任务为赤陶色，已完成为浅色，进行中为强调浅底，里程碑为菱形。

源码有误时页眉以警示色提示，舞台保留上次成功的图（淡化显示），底部横幅给出行号、原因和该行内容（UIA 角色为 alert）。整个舞台点击即编辑源码；支持撤销上一步。修改后图表淡入（250 ms，关闭“动画效果”时不播放）。高度低于 120 DIP 时显示单行胶囊摘要。

## 文字测量

布局通过 `TextMeasure` trait 取得文字宽度，可注入：

- 组件运行时使用宿主的 `RenderService::measure`。应用端（`panel_manager.rs` 的 `HostRender`）现在用 `pecofence_render::TextFormatCache::measure` 走 DirectWrite，字体为暖纸正文字体（`FontRole::PaperBody`，即捆绑的 Noto Sans SC，缺失时回退 Segoe UI Variable）。测量只在源码变化、重新布局时进行，结果随布局缓存，不在每帧调用；服务不可用时回退到估算。
- 测试和回退使用确定性的 `Estimate`：ASCII 约 0.56 em（大写 0.64 em）；中日韩、谚文和全角字符 1 em；组合附加符号、控制字符和零宽字符（ZWSP、ZWJ、变体选择符、BOM 等）为 0；其他字符 0.6 em。

节点标签超过 192 DIP 时自动换行（先在空格处断，再在中日韩字符之间断，单个词过长才在词内断），节点随行数增高，常见长度的标签不再被裁剪；连线标签同理，最宽 160 DIP。甘特图任务名列宽在布局时测量一次。

## 取舍

从 Pele 借鉴并已实现：预处理 → 识别 → 注册表 → 解析 → 布局 → 绘制的流水线；可注入的确定性文字测量；分层布局中的虚拟顶点与标签节点；复合（子图）边框的简化版；以布局不变量为主的测试。

刻意未做：Pele 的完整复合布局（子图作为整体参与排序与定位）、Pele 其余的连线走线目标（如减少拐点；端口分离与轨道分离已实现）、从 Mermaid 移植的解析器规格用例（许可与体积考虑，测试自行编写）、其余图表类型。

## 验证与限制

`cargo test -p pecofence-plugin-widgets` 覆盖：流水线（front matter 与注释、关键字识别、暂不支持的类型与行号）；文字测量（零宽与组合符号、宽字符、换行规则）；解析（形状、链、分组、标签、子图嵌套、错误行号、甘特依赖、分组展开不超过连线上限）；布局不变量——在四个方向、带标签、长连线、环、自环、子图和若干伪随机图上检查：节点框互不重叠，连线线段不穿过任何节点框且均为水平或竖直，同一节点上不同连线的端点相距至少 3 DIP，任意两条连线的线段不共线重叠（两个报告用例在四个方向上都检查），标签不压节点且位于自身连线上，子图边框包住成员且不圈进外部节点，同一输入布局结果完全一致；场景（节点在舞台内、箭头数量、直线与今天线确实绘制、子图边框与标题、标签不压节点、错误横幅、空白与胶囊状态）。

限制：尚未在 Windows 设备上做视觉、IME、屏幕阅读器验收；舞台缩放到 69% 以下时节点文字按 9 DIP 下限绘制，可能被裁剪；自环的标签不预留空间；子图边框在无法避免圈进外部内容时省略；虚线连线以浅色细线表示。
