# 用户需求与原生设置替换清单

状态：需求基线与替换验收标准；**原生设置尚未实现，WebView2 尚未移除**。

当前源码基线：PecoFence `550fa1b`。既有桌面功能和 SPM 动作修复不等于新原生界面已验收。
本清单用于确定用户能够完成的任务，不以模块、trait 数量或编译通过代替功能完成。
实现进度见 [ROADMAP.md](ROADMAP.md)，操作说明见 [FEATURES.md](FEATURES.md)。

## 1. 产品边界与优先级

- **桌面核心**：独立的 Windows 11 x64 桌面整理工具，无账号、无 SPM 时也能使用。
- **可选业务集成**：授权用户使用私有 SPM 后端查看业务数据。公共客户端不携带私有业务配置、凭据或数据。
- **维护者工具**：编译、绑定生成、CI、Dependabot、协议契约检查、lab 实例和发布工具不是普通用户的操作入口。
- **本轮原生化范围**：替换设置窗口。栅栏、托盘菜单、文件操作对话框和 SPM 面板已经是原生界面。
- **产品网站**：维护者已决定移除网站源码及其构建/部署流程，不作为产品需求或后续交付项。

优先级：

- **P0**：桌面基础能力或设置替换前必须保留、验收的能力。
- **P1**：可选 SPM 产品闭环；不阻塞无 SPM 的桌面版本。
- **P2**：非必要视觉增强；不以它为理由保留浏览器运行时。

下面的“已有实现”只说明存在用户入口和实现路径，不表示所有 Windows 实机组合已经通过。
不要求旧配置、旧前端消息或旧接口兼容，但必须保留原文件，不能静默丢失用户数据。

## 4. 原生设置必须覆盖的功能

采用一个原生设置窗口、五个任务页，以及跨页的保存/恢复/冲突状态区。
这是功能组织，不要求照搬网页布局或创建五个不同的状态所有者。

### N01：常规与外观（P0）

- 显示语言：跟随系统及现有十种语言。
- 随 Windows 启动、隐藏真实桌面图标、双击空白处 Quick Hide、Win+D 行为。
- Fluent/Liquid Glass，跟随 Windows/应用模式及浅色/深色。
- 默认图标大小、图标着色、强度和 Chameleon。
- 悬停展开、点击展开、悬停才显示标题、不活动时隐藏滚动条、移动吸附。
- Peek 开关、背景压暗、现有热键选择。
- 开关应说明预期行为；设置接纳不能冒充 OS 注册或隐藏已经成功。

### N02：窗口与内容选项（P0）

- 选择内容并标明所属窗口；从栅栏菜单打开时定位到对应内容。
- 内容选项：名称、图标大小、间距、门户导航与标题文件夹图标。
- 窗口选项：不透明度、色调、标题颜色/字号、自动高度、锁定、Quick Hide 排除、停靠顶部。
- 门户专用选项只对门户可用；文件视图选项不能应用到业务面板。
- 一个窗口有多个标签时，窗口级选项说明会影响哪些内容。
- 内容移动、删除或工作区替换后，旧编辑目标必须被拒绝/重新选择，不能误改另一个窗口。

### N03：整理规则（P0）

- 自动整理开关、立即应用、默认目标，以及当前协议支持的规则操作。
- 图片、音乐、视频、压缩包、安装包和待清理模板。
- 创建、编辑、启停、优先级调整和删除规则。
- 目标只包含文件集合；门户和业务面板不能作为虚拟分类目标。
- 条件：类型、扩展名、名称包含/不包含/开头/结尾/精确匹配/通配符、快捷方式目标、
  创建时段、星期、大小范围、闲置天数、来源、仅文件/仅文件夹。
- 一个规则可添加、修改和删除多个 AND 条件；范围、空值和数量在应用边界校验。
- 草稿与最新工作区分离；冲突或失败时保留草稿，由用户决定重试或放弃。
- 普通用户不需要编写 JSON、编辑配置文件或使用命令行完成这些任务。

### N04：布局、备份与恢复（P0）

- 命名并保存布局快照，列出时间/范围，恢复和删除快照。
- 选择两个显示器并交换布局；不足两个显示器时说明不可用原因。
- 原生文件对话框导入/导出受支持的配置；列出并恢复可用备份。
- 加载失败时显示只读原因；允许打开配置目录、导出可用状态、导入、新建或接受恢复候选。
- 替换、恢复和删除操作采用与风险匹配的确认；既有原文件必须保留。
- 保存状态、失败重试、取消退出和明确放弃未保存修改不因换界面而消失。

### N05：关于与诊断（P0）

- 独立产品名称、版本和适用的许可/归属信息。
- 配置路径、打开配置目录、基本资源/项目统计。
- 查看真实桌面图标状态，恢复显示或重新隐藏的现有修复入口。
- 错误信息能定位问题，但不自动导出凭据、企业配置、私有源码或业务数据。

### N06：跨页交互与无障碍（P0）

- Tab/Shift+Tab、方向键、Enter、Esc 有确定行为；无键盘死角，焦点在提交后保持合理位置。
- 标准控件提供名称、类型、值、状态和合理焦点顺序；动态提示不只用颜色表达。
- 高对比、屏幕阅读器、100%/150%/200% DPI 和文字缩放下控件不裁切且可以到达。
- 现有十种语言的静态标签、动态错误和布局可用；长译文不会隐藏关键按钮。
- 后台保存/刷新/主题更新不覆盖正在编辑的字段、不意外改变所选规则或移走焦点。
- 正常关闭、重复打开和工作区替换不会让旧窗口发送有效修改。

### N07：可信状态（P0）

界面必须区分：

1. 草稿尚未提交；
2. 修改已接纳但尚未保存；
3. 当前工作区修订已提交；
4. 保存失败或可选备份退化；
5. 冲突、目标失效或只读；
6. 正在退出并等待保存，用户可取消退出。

OS 集成的“期望/实际/失败”是后续必须完成的用例状态，不能通过新原生控件假装已经具备。
状态更新不得将旧工作区/旧修订的成功用于确认当前修改。

### N08：浏览器非功能内容（P2）

网页宣传文案、hero 卡片、SVG 折射预览、CSS 过渡和浏览器特有交互不要求逐像素复制。
如果保留外观预览，必须标为示意，并且不能引入浏览器。
它们可以删除或用原生示意替代；不属于规则、保存、恢复等功能对等的阻塞项。

## 5. 技术选择与边界

选择 **Win32 原生标准/通用控件** 为设置表单主体，复用现有 Windows 宿主。
需要的视觉呈现可使用现有原生渲染，但不自绘替代本可直接获得键盘和辅助功能的表单控件。

不采用 Electron/CEF/WebView 替代 WebView2，也不为了设置窗口引入新的浏览器。
WinUI 3 的视觉和控件能力有优势，但需要另行承担 Windows App SDK 的部署与运行时成本；
本轮优先减少运行依赖并完成既有任务，故不选择它。

- 界面只持有选择、输入草稿和呈现状态。
- 复用类型化设置、规则、工作区和持久化用例，不直接写 `Config` 或注册表。
- JSON 交换属于现有 WebView 适配边界；原生内部调用应使用类型，不为“复用”保留 JS/浏览器消息通道。
- 内容/窗口身份、工作区激活和修订校验仍然有效；删 Web wire 不等于删冲突保护。
- 不建另一份可变设置状态、不新增通用服务框架、不同时改写领域规则。

## 6. 完整移除 WebView2 的验收门槛

以下是替换任务清单，**不是已完成事项**：

- [ ] N01–N07 的现有功能全部有原生入口；不存在“打开旧网页编辑规则”的兜底。
- [ ] 原生控件到真实用例/保存结果的正常、失败、冲突、恢复和退出测试通过。
- [ ] Windows 键盘、辅助功能、语言、DPI 和 OS 集成实机检查有版本及结果记录。
- [ ] 删除 `WebEnvironment`、WebView controller、页面加载、前端脚本/样式和专用消息桥。
- [ ] 移除 `windows-webview` 依赖及不再需要的传递依赖，更新锁文件。
- [ ] 替换 HTML/JS/browser 测试和 CI 调用；保留或重新表达其领域/用例/保存语义覆盖，不通过删测试让 CI 变绿。
- [ ] 检查静态/延迟 PE imports、动态加载路径及进程树；程序没有 WebView loader/runtime 依赖或浏览器子进程。
- [ ] ZIP、MSIX、安装脚本和 lab 清单不再要求/携带 WebView2Loader；运行、开发和许可说明一致。
- [ ] 干净 Windows 环境无 WebView2 Runtime 时仍可启动并使用全部设置。
- [ ] 旧浏览器 profile 和用户配置不自动删除；清理代码不产生机器外部的破坏性动作。
- [ ] 记录旧/新版本启动、打开设置耗时、空闲资源和发行体积；性能目标基于测量，不能只凭“原生”判断。

产品网站及其构建/部署流程已独立移除；构建脚本或 GitHub Action 使用 Node 并不等于桌面产品携带浏览器。

## 7. 实施顺序与完成定义

1. 提取设置只读模型和类型化调用边界，保留既有校验、修订和提交所有权。
2. 实现原生窗口、常规设置及状态区，完成第一条端到端用例。
3. 补齐窗口/内容选项、规则编辑、布局/恢复和诊断入口。
4. 完成原生自动化与实机验收，替换测试和运行时/打包依赖，删除 WebView 路径。

实施期间 WebView 可暂时作为唯一生产设置入口；测试中的原生切片不能被宣传为完整替代。
最终只保留一个正式设置入口和一套应用用例。
完整替换需要功能对等，不需要旧 UI 布局或消息协议兼容。

每项需求完成需要：可操作入口 → 校验 → 实际效果/结果 → 状态与保存反馈，
并记录失败路径及未执行验证。实现、提交、发布和用户验收是不同状态。
