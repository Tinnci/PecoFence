# 默认布局与小组件

设置 → 布局 → 默认布局与小组件提供三个独立操作：

- **恢复默认排布**：重排当前显示器布局中已识别的默认内容。保留正文、待办、文件归属、分类规则、标题及业务身份；不新建已删除的文件分类。
- **补齐默认组件**：补齐缺失的时钟、日历、便笺、待办。先识别已有组件；其他显示器布局里已有同一默认组件时复用其内容和业务实例。重复执行没有新增内容时不额外保存快照。
- **恢复默认外观**：恢复主题、小组件纸张、图标色彩和当前布局的窗口外观覆盖；保留位置、内容、图标尺寸、分类规则、桌面路径及启动设置。

有实际变化时自动保存操作前快照。快照可以恢复原排布和外观；恢复期间保留仍存在的小组件的最新正文/待办配置。新字段是可选字段，旧快照继续只恢复布局。操作受设置会话版本、确认对话框和只读门禁保护；候选配置完整验证成功后才替换内存文档，沿用异步持久化和失败重试。

## 模板与适配

模板 v1 位于 `crates/core/src/default_template.rs`，以稳定角色标识 `default.programs/folders/documents/inbox/clock/calendar/note/todo` 识别内容，和随机业务 UUID 分离。角色不依赖可修改的标题；旧工作区首次使用操作时通过原分类规则、既有分类标题或组件 provider 识别，保留原 ID。

首次启动和明确新建工作区共用这一模板：右侧四个文件分类，左侧时钟/日历/便笺/待办。布局在主显示器工作区的 DIP 中规划，文字比例通过实际字体网格进入小组件 span 计算；绘制 DPI 只用于物理坐标转换。各内容的图标尺寸保留，不能拿全局图标大小覆盖其网格。当前用户配置在安装/升级时不自动套用模板。

空间足够时每个角色独立成窗；空间不足时使用标签组。已有自定义窗口占用目标区域时保留其位置，把默认内容作为标签加入，避免覆盖或丢弃自定义内容。分组窗口不再按当前激活小组件的 span 改变整窗大小，因此切换标签不会导致窗口反复跳动。

## 验证与边界（2026-10-20）

核心矩阵覆盖 1920×1040、1280×720、768×1024、640×480 DIP，96/120/144/192 DPI，100/150/225% 文字比例：全部角色可访问，生成窗口在工作区内且不重叠。窄屏会减少窗口数量，通过标签访问内容；该矩阵证明规划几何，不能替代真实显示器像素或屏幕阅读器验收。

Windows 回归覆盖稳定业务数据/身份、重复操作、旧数据识别、跨显示器布局复用、只读/预算失败的原子性、快照撤回与最新正文保留。设置组件回归覆盖三个具名入口和确认后的类型化命令。`scripts/test-default-template.ps1` 使用隔离实例，通过真实 WinUI/UIA 取消、补齐、重复补齐、重排、恢复外观和恢复快照，再读取落盘配置核对便笺、历史和原用户启动项。测试不对用户安装发送按钮动作，不上传日志或工作区。

交付验证：核心 64 项、Windows 应用 193 项普通回归通过；另显式运行原生设置窗口巡检 1 项，通过全部页面及多语言/窗口关闭重开流程。真实按钮脚本报告 `passed=true`、补齐 2 个缺失组件、重复补齐无新增、4 份快照、外观快照恢复成功、便笺身份与内容及用户启动项保持一致。两平台严格 Clippy、Windows 构建及格式检查通过。证据保存在本机 `.cache/default-*`，不作为源码提交。
