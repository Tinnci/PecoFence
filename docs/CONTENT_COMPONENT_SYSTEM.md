# Direct2D 桌面内容组件约定

更新：2026-10-17。状态：首轮代码收敛已接入；真实 Windows 视觉、DPI 和辅助技术验收待完成。

## 为什么需要收敛

本轮检查发现的是具体实现分歧，而不是 Direct2D 能力不足：

1. 插件 FrameInput.text_scale 固定为 1.0，系统文字尺寸没有进入插件布局。
2. 插件主题只由 ThemeMode 生成另一套颜色，忽略真实栅栏前景色、强调色与材质。
3. SPM 的根 pane 绘制自己的实色底，便笺/时钟等则使用宿主材质。
4. 各插件单独选择文字、圆角、裁剪策略；标题字号不同。
5. 窗口或字体尺寸变化时，部分插件只按业务修改更新 layout_revision。
6. device_epoch 曾只有 DPI，没有真实图形设备代次。
7. 时钟的默认 Capsule 内容高度只有 48 DIP，原布局仍按大时钟安排 72 DIP 时间与日期，存在裁切风险。
8. Canvas 在裁剪前改写文字与位图目标矩形，可能导致重新排版或缩放；本轮改为保持布局几何，由 D2D clip 限制实际绘制。

## 当前分工

```text
实际 Fence Theme + 系统文字尺寸 + 每窗口 DPI/设备代次
              ↓
plugin-api::design（平台无关设计与几何规则）
       ├─ 文件适配器：ItemLayout → FileScene + FileItemGeometry → FenceChrome
       ├─ chrome 适配器：FenceChrome / Direct2D
       └─ 插件布局适配器：WidgetFrame / prepare_scene → Scene → Component → Canvas
              ↓
宿主 Panel 的 DIP→物理像素变换 → Composition
```

统一的是呈现规则、主题来源、几何和组件绘制契约；不是让每个文件都创建一个独立窗口，也没有把业务数据迁入渲染层。

- `crates/plugin-api/src/design.rs`：字体族、字号阶梯、内容边距、控件圆角、PixelGrid、ContentScale、Component 和 LayoutTracker。
- `crates/render/src/theme.rs`：字体族引用共享定义；材质和文件选中态仍由宿主 Theme 拥有。
- `crates/render/src/fence_chrome.rs`：文件与栅栏 chrome 使用共享字号和像素对齐；系统自定义图标标题字体仍保留。
- `crates/plugin-widgets`：便笺、待办、时钟、日历通过同一个 Component 绘制器绘制，绘制/命中/语义矩形来源一致。
- `crates/plugin-spm`：复用 Component 与缩放规则，根 pane 不再覆盖宿主背景；业务状态仍由 SPM 契约表达。
- `app/panel_manager.rs`：从实际 Theme 前景、背景和强调色生成插件快照，不再只按深浅模式复制一套配色。

文件网格、列表、chrome 与专用日历/时钟仍有各自布局。第一轮没有将全部自绘控件重写成通用 UI 框架；插件的 hover/pressed/focus 已在第二轮接入宿主共享状态机；高对比策略和所有固定布局尺寸仍需逐项收敛与实机验收。

## DPI 与文字缩放

二者必须分开：

- 布局、命中、语义边界以 DIP 表达。
- 每窗口 DPI 仅由宿主 Panel 转换到物理像素：`px = dip × dpi / 96`。插件不得再次乘 DPI。
- ContentScale 使用系统无障碍文字比例（100%–225%）缩小布局输入视口，再同步放大输出几何、字号和局部圆角。这样现有响应式断点能看到变小的可用空间，避免只放大字而保留原命中框。
- Todo 分页容量使用缩放后的布局高度，避免大字与页脚重叠。
- FrameInput.text_scale 来自宿主缓存的系统设置，在设置广播时刷新，不逐帧读取注册表。
- 设备标识由真实设备代次与窗口 DPI 共同构成，避免同 DPI 的设备重建复用旧标识。
- PixelGrid 统一物理像素对齐；它不是文字放大比例。

这套缩放策略会一起放大插件控件的几何间距。特别狭窄或低矮窗口仍需要专用响应式布局，不能依赖放大或裁剪代替可用性检查。时钟本轮已增加真正的低高度布局。

## 新组件接入规则

1. 业务只产出文本、动作和语义状态，不硬编码深浅主题颜色。
2. 从 ThemeSnapshot 使用语义色；没有快照时使用共享 fallback。
3. 优先使用共享字号、边距和控件圆角；专用时钟大字等保留明确的语义例外。
4. 先在 ContentScale.logical_viewport 布局，再映射一次实际 DIP 几何；绘制、命中与语义节点使用相同矩形。
5. Component 统一背景、文本和局部裁剪，文本字体角色不因无障碍放大而意外从 Caption 变为 Display。
6. 宿主绘制背景材质，插件不能无条件铺一块自己的不透明背景。
7. 布局/动作映射变化应推进 layout_revision；颜色和纯绘制更新不应无故推进它。
8. 点击完成前检查挂载、布局、命中树及设备身份；DPI 切换或重排期间不得触发旧坐标对应的操作。
9. 不改变已有配置版本、持久化回执、文件拖放与生命周期协议。

## 第二轮：统一插件交互与绘制复用

- 宿主为所有插件提供同一套悬停、按下、键盘焦点反馈，使用实际主题和 DPI 对齐；反馈圆角随文字布局缩放。
- Tab / Shift+Tab 在当前完全可见的控件间导航；Enter / Space 调用已聚焦动作并抑制按键自动重复。Ctrl/Alt 组合继续交给已有窗口处理。
- 焦点丢失、鼠标捕获取消、控件消失会清理相应状态；指针命中限制在实际可见内容视口。
- 按下与抬起按控件 ID 验证，不因两个控件恰好调用同一动作而跨控件触发；挂载/布局/设备变化也会取消过期手势。
- 鼠标移入同一控件不重复绘制；控件变化时重绘已提交画面与反馈，不调用 provider.prepare_frame，不推进业务或布局修订。
- 这一版仍重绘整个内容 surface，没有宣称实现独立反馈 surface 或局部脏区更新。
- 每个插件内容宿主复用有界 DirectWrite TextFormatCache，按字体角色、DIP 字号和字重缓存，上限 128 项。文字内容和显示 DPI 不进入字体格式键；真实字号变化会使用新格式。缓存随宿主释放。

本轮纯逻辑测试覆盖控件级键盘导航、同动作不同控件、重排/DPI 变化期间的点击取消、反馈绘制。Windows 原生字体缓存测试只验证 DirectWrite 格式复用与容量边界，不能代替 UI 字体质量或键盘实际可达性验收。

### 第二轮验证记录

- Windows 上运行的 render 测试：40 项通过，含本次新增的原生 DirectWrite 缓存测试及既有 DPI/像素/材质/动画数学测试；这不代表执行了真实 GPU 场景或输入操作验收。

- 窗口变小后会清理被裁切控件的键盘焦点，避免 Enter/Space 触发不可见动作。
- 鼠标与键盘操作的实际系统可达性、跨屏拖动和最终视觉一致性仍待实机验收。


## 第三轮：不可变场景与候选提交

阶段目标和后续顺序见 [CONTENT_ARCHITECTURE_GOALS.md](CONTENT_ARCHITECTURE_GOALS.md)。

- `plugin-api::scene` 新增共享 Scene/SceneNode/NodeStyle。绘制、命中和语义从同一份节点产生；语义名称可以与可见文字不同。
- 验证节点几何、样式、ID 与父子关系；错误场景不能进入绘制。便笺、待办、时钟、日历及 SPM 已接入；WidgetFrame 现在只是准备期构建器，完成后返回 Scene。
- 插件内容与反馈使用 `Panel::draw_candidate`。回调和 EndDraw 成功后才发布 surface；失败不替换当前插件画面与命中树。文件渲染仍使用原 draw 路径。
- surface 按需双缓冲并复用，增加相应像素内存；resize 与设备重建不承诺保留旧像素。Provider 的业务状态不是这个提交机制的回滚对象。
- 尚未把文件网格/列表转换为 Scene，也未实现局部脏区绘制；具体边界已记录，避免误将此阶段视作完整 UI 框架重写。

## 第四轮：文件几何与提交边界

文件网格/列表/详情通过 FileScene 固定实际绘制的动画矩形，命中、框选、拖动图像和原生重命名位置复用它。FileItemGeometry 统一图标和名称文字位置，修复原先编辑区域与文字绘制 inset 不一致的问题。展开名称按最上层图像处理命中。

文件内容现在也采用候选 surface 提交；详细列表使用支持 Clip 的 draw_candidate_ex。surface_epoch 表示存储资源身份，阻止尺寸改回原值、设备重建或切换复用 Panel 后恢复旧命中信息。插件同时采用这个存储身份约束。

此阶段仍保留文件专用绘制器，不声称已把文件与插件合并成同一个文本/图像场景树，也未接入完整文件 UIA 语义桥。共享场景原语、行字体/分组标题缩放及实际桌面输入验收继续作为目标工作。

## 第五、六轮：排版、语义与失效收敛

- 文件列表/详情正文、表头、分组和空状态共用 ContentTypography 资源包，按系统文字比例更新。文字带高度来自测量，分组高度不再硬编码；列文本拟合与裁剪防止放大后串列。
- 系统设置刷新会重建相应字体、清除拟合标签和布局动画，再重排与调整自动高度。表头命中也读取已发布 FileScene。
- SemanticNode 支持默认 u64 与文件 ItemId；文件语义、命中共用冻结矩形，名称保留完整文字。此项没有接入实际 Windows UIA provider。
- 插件失效改用 Clean/Feedback/Content/Layout，待布局不会被反馈重绘清除；恢复隐藏内容时先处理布局，内容绘制成功才清除未完成工作。
- WidgetElement 以具名字段表达配置，代替多位置参数调用；没有引入第二套主题或 DPI 变换。
- Windows 宿主集成回归覆盖候选部分绘制后失败、已提交输入保留、反馈不调用 prepare、存储更换及隐藏跳过绘制。

## 第七轮：标题排版与尺寸生命周期

FenceTypography 统一标题、标签页、折叠计数及文件内容字体。标题高度从最大标题实测行高派生；应用初始主题、主题重建和文字设置变更同步该值，布局与标题命中不另行乘文字比例。

文字设置变更清理标签宽度缓存、标签位移动画和旧 infotip，取消旧尺寸的高度动画并按折叠目标结算。已展开的手动高度尽量保留，过低时至少留一像素内容；折叠窗口使用新标题高度，缩小时可恢复原值。窗口 resize 在无 view 借用时执行。

### 第七轮验证记录

- 实际 D2D 绘制覆盖独立显示 DPI 与文字比例、三档标题和折叠计数；不包含显示器像素读取或真实窗口输入验收。

## 第八轮：标题栏提交快照与原生交互验证

ChromeScene 将标题、标签页、返回和折叠按钮的绘制几何冻结到成功提交的 surface；命中、拖动抓取位置和 tooltip 读取同一快照。标签使用稳定 ContentId，保留完整名称，过期存储、活动内容、DPI、设备代次或尺寸不再复用旧输入。标题绘制也采用候选 surface，仅绘制成功才发布。

Windows 原生测试共 104 项通过（render 44、窗口/宿主 43、布局 17）；Linux 平台无关测试 44 项通过，Windows 应用严格 Clippy 通过。隔离配置的原生 GUI 脚本验证标签合并、拖动排序、恢复排序、取消拖动和折叠/展开，6 次快照均无残留 capture/tab_drag；展开语义节点 16、折叠 4，无 ERROR/PANIC/device-loss。运行的是本地 NTFS 上的开发构建，显示 DPI 为 96；不代表物理鼠标、跨显示器、视觉像素或完整 OLE 验收。UNC 夹具监视与未启动 SPM daemon 的警告不纳入本次验收。

候选双缓冲覆盖插件、文件正文和标题栏；每个 surface 的额外显存约为宽×高×4 字节。设备重建/resize 期间不保证保留旧像素，提交快照也不代表显示器扫描输出已完成。高对比、Windows UIA provider、图像/材质场景收敛与真实跨屏输入仍待完成。


## 第九轮：插件输入取消与可交互生命周期

确认并修复：Esc 原来流入文件键盘处理器，未直接清除插件按下快照；重绘若保留布局身份和命中矩形，后续松键仍可能触发动作。插件输入现在有统一的指针取消、全部输入取消和单次松键解析入口。Esc、WM_CANCELMODE、失去焦点、捕获变化各自明确取消范围；原生捕获释放放在 view 借用之外。系统取消/捕获变化保留键盘焦点，Esc/失焦清除焦点；标题拖动的 Esc 继续交给标题处理器。

折叠、折叠/展开动画、淡出、退役、隐藏或未激活内容不接受插件正文输入。成功提交的正文帧可以保留供动画使用，取消时通过反馈重绘去除旧焦点/按下墨迹，不为清除反馈重新准备业务数据。

原生宿主回归增加同一提交帧上的正常松键、重复松键、指针取消后松键、完整取消后松键和重复取消断言，检查保留焦点的范围、帧身份及 prepare 调用次数。此回归验证宿主状态和真实 Composition 反馈绘制；不代表完整原生消息路由、物理键鼠或跨屏操作已验收。

本轮验证：Windows 窗口/宿主原生测试 43 项通过（含扩展的取消回归）；Windows 应用 all-targets Clippy（-D warnings）通过；Windows 开发版构建及 Windows App SDK Runtime 2.5.1 暂存成功。高对比、UIA 与完整桌面输入/跨屏验收仍为未完成项。


## 第十轮：资源失效与原生捕获释放

资源绑定变化或隐藏绘制原来直接丢弃 pressed，因而丢失该手势的 ReleaseCapture 责任。现在取消会保存独立的待释放标记，重复绑定/取消不覆盖该标记；取出后只执行一次。WM_CAPTURECHANGED 确认 OS 已移交所有权，会清除旧请求。

窗口过程入口在派发新手势前处理旧请求，出口使用 RAII 边界覆盖提前返回和原生 resize/DPI/重绘中的取消。取出标记时持有 view 借用，实际 ReleaseCapture 则在借用释放后执行，允许同步 WM_CAPTURECHANGED 回调。请求只对仍拥有捕获的 HWND 生效。

控制窗口命令也可能在 fence 窗口过程之外重绘，因此重绘路径即使返回错误，也会为待释放请求投递专用唤醒消息。该消息只处理待办效果，不模拟 WM_CANCELMODE，已清理的旧唤醒不会主动取消后来开始的新手势。

Windows 窗口/宿主测试 44 项通过。扩展回归检查取消效果仅取出一次、资源变化后重复绑定不会丢失请求；新增隐藏 HWND 原生测试实际调用 SetCapture/GetCapture/ReleaseCapture，验证所属窗口、重复释放和同步通知。未将该测试等同于真实跨屏拖动、完整宿主消息路由或全生命周期无竞态证明。

本轮 Windows 应用 all-targets Clippy（-D warnings）、开发版构建和固定 Windows App SDK 运行时暂存均通过；高对比、UIA 和真实跨屏交互验收继续保留。


## 第十一轮：捕获效果归属窗口

复查卸载和标签切换后确认，组件内的待释放 bool 生命周期过短：release_panel_view 或 set_content 替换对象会连同待办效果一起销毁。窗口现在持有共享的待释放 Cell，插件只持有引用；PluginPanelContent::drop 登记取消，窗口仍能在组件已为空时完成原生释放。

窗口过程入口先绑定仍存在的插件资源，再处理窗口级待办；没有插件时也必须先释放旧捕获，才交给文件或标题处理器。with_view 和 try_apply_panel_update 增加借用结束后的效果处理边界，覆盖控制窗口发起的更新、组件替换和卸载，不依赖将来的一次鼠标移动。保留专用异步唤醒作为其他重绘入口的处理路径。

原生宿主回归扩展为：成功提交并按下控件后销毁整个 PluginPanelContent，窗口持有的待释放请求仍然存在且只消费一次。此测试证明组件销毁不会丢弃标记；真实标签切换消息链、物理输入与跨屏验收仍需独立验证。

本轮 Windows 原生窗口/宿主测试 44 项、应用 all-targets 严格 Clippy、开发版构建及运行时暂存通过。高对比、UIA 和真实桌面输入/跨屏验收仍未完成。


## 第十二轮：系统高对比主题基础通路

确认缺陷：ThemeSnapshot 虽有 high_contrast 字段，宿主此前始终保留默认 false；实际颜色只来自深浅主题和玻璃背景。平台层现在只读查询 SPI_GETHIGHCONTRAST 与 GetSysColor 的 COLOR_WINDOW/COLOR_WINDOWTEXT 配对，不修改系统设置。实现依据：[高对比参数](https://learn.microsoft.com/en-us/windows/win32/winauto/high-contrast-parameter)、[HIGHCONTRASTW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-highcontrastw)。

Theme 增加明确的高对比状态，以不透明系统背景和前景替换文字、边框、焦点与选择轮廓；选择不填色，以保持 Window/WindowText 配对，不猜测反色文字。普通 accent、玻璃样式和壁纸亮度不能覆盖该配色。WM_SYSCOLORCHANGE 纳入主题刷新；在高对比保持开启但系统前景/背景变化时仍会刷新，而不是仅比较 mode。

宿主快照同步高对比标记与系统文字色，状态角色同样使用可读前景，业务状态继续由文本表达。共享控件反馈在高对比时画不透明轮廓，避免把普通半透明反馈覆盖到文字上。标题绘制选择 Solid 背景，并忽略单栅栏透明度、tint、自定义标题文字色和标签颜色；高对比显示标题，不使用标题悬停隐去策略。文件正文和插件使用同一 Theme/ThemeSnapshot；字体、DPI 和文字比例约定不变。

验证：Windows render 47 项、主题宿主 5 项、窗口/宿主 44 项通过；Linux 平台无关测试 45 项通过。新增回归覆盖深/浅/自定义系统配对、主题 epoch 与模式恢复、轮廓反馈；实际 D2D 绘制在 96/144 DPI 下使用被独占借用的 GPU material，确保高对比路径不会访问玻璃采样，并带低透明度/自定义 tint 参数提交。

边界：尚未切换用户真实 Windows 高对比设置或做屏幕像素验收。原生菜单、所有按钮的悬停/焦点可见性、完整跨屏/文字比例矩阵仍需逐项验证完善；基础通路通过不代表完整高对比可访问性验收。UIA provider 仍未接入。

本轮 Windows all-targets 严格 Clippy、开发版构建和固定 Windows App SDK 运行时暂存通过。上述实机与 UIA 未完成项继续保留在整体目标中。


## 第十三轮：高对比控件状态与场景边框

进一步确认两处缺陷：文件选中悬停的 HOT_SELECTED_LIFT 会重新给透明 selection_fill 增加 alpha，改变系统背景；标题返回/折叠按钮的 hover/pressed 则因普通填色已透明而失去状态反馈。文件状态在高对比时改为仅描边，不再经过普通混色分支；标题、标签、返回和折叠按钮使用共同的内对齐轮廓。折叠按钮在高对比静止状态也保持显示。

平台无关 design::contrast_outline 统一控件轮廓的像素对齐、粗细和尺寸下限，原生 chrome 与插件悬停/按下/键盘焦点共用它。回归覆盖 100/125/150/200% 显示比例下描边外缘落在整数设备像素上，不增加输入缩放。

NodeStyle/Component 增加可选 stroke，场景准备时验证颜色和正有限宽度，公共 painter 在原节点内部画边框并保持原裁剪和文字矩形。日历在高对比时用持久边框标记选中日，当天仍保留字体强调；不为装饰新增语义或命中节点。回归使用独立文字比例，验证原有 32 个命中目标及选中节点的绘制、命中、语义矩形一致。

新增命令记录回归验证边框位于原矩形内部、文字使用原始矩形且裁剪平衡；非法颜色、零/负/非有限边框宽度被拒绝。Windows D2D 回归扩展到返回/折叠按下、文件 hover/selected/pressed/focused 状态，并继续验证高对比不访问 GPU 材质。

这些结果仍不能代替屏幕像素/真实输入验收；原生菜单、UIA provider 和真实跨屏矩阵继续属于整体目标的未完成项。

本轮验证：Linux 平台无关测试 48 项，Windows render 48 项、主题宿主 5 项、窗口/宿主 44 项通过；Linux 库及 Windows 应用 all-targets 严格 Clippy、Windows 开发版构建与运行时暂存通过。


## 第十四轮：菜单主题边界与原生交互验收

菜单使用 WinUI MenuFlyout，并未自行画深浅/高对比菜单颜色。依据 [Windows 对比主题说明](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/high-contrast-themes)，框架默认参与高对比调整。本轮显式约定菜单请求策略：检测到系统高对比时请求 WindowTheme::System，普通模式继续按保存的菜单深浅偏好请求 Dark/Light；每次打开时读取系统状态。标题可见性目标也纳入 high_contrast，与 renderer 的强制显示策略一致。

新增菜单策略优先级回归。实际隔离 WinUI 菜单测试最初在 UIA SetFocus 调用失败，另一次菜单提前关闭并返回 0，原因未确认；未据此认定是应用渲染或高对比缺陷。诊断确认菜单可获得前台、首项可聚焦且已持有焦点；测试脚本改为前台归属校验下的 Home/Enter 和 Esc，去掉冗余的 UIA SetFocus。没有降低前台进程检查或向其他应用发送键盘输入。

修改后的仓库脚本完整运行通过：深色勾选项、禁用项、浅色菜单、子菜单展开/执行、键盘选择、Esc 取消及重复打开；返回命令依次为 11、22、0，测试进程正常退出。通过 UIA 检查 ToggleState 和 IsEnabled；查看了本地深浅菜单截图，文字、勾选、禁用和分隔线可见。测试只操作隔离进程，临时运行时由脚本清理，未修改用户配置/系统高对比设置。

本轮菜单普通单元测试 2 项及显式执行的原生 live 测试 1 项通过；窗口/宿主回归 44 项通过。严格 Clippy、Windows 测试目标与开发版构建通过。菜单验证发生在当前普通系统配色下；真正开启/自定义 Windows 高对比后的 UIA/像素验收仍未完成，不能把菜单 UIA 通过外推为桌面 D2D 内容已有 UIA provider。


### 延迟的原生提示（2026-10-18）

infotip 属于提交场景的消费者：文件目标保存 ContentId + ItemId，标题来自成功发布的 FileScene 语义；标题页和门户向上同样保持稳定内容身份。定时器到期后必须按当前物理指针重新查有效场景，不能用曾经的索引/坐标直接显示。显示与自动隐藏分别保存真实截止时间，以隔离 KillTimer 后仍在队列中的旧消息；借用冲突只重试，不丢弃待办。此路径继续使用系统 Tooltip，不自建文字编辑或取代 UIA。


### 交互生命周期与外部回调（2026-10-18）

interaction::InputLifecycle 为文件、chrome 与插件提供共同的窗口/正文可用性语义。淡出、退役、隐藏关闭窗口动作；折叠动画只关闭正文动作，保留标题入口。已提交的画面/几何可以留作动画资源，但不因此继续接受动作。view 内只清理状态和登记窗口拥有的捕获效果，ReleaseCapture/拖动取消在借用外执行。

OLE 回调跨越本地数据对象或菜单循环时，应先保留命令候选，返回前核对稳定目标与生命周期，再入队。文件夹目标使用完整 ItemId 和路径；插入位置携带完整顺序。返回 Move/Copy/Link 与命令入队一致，不能把 UI 命令入队称为磁盘操作已成功。

### 只读 UIA 发布边界（第十七轮）

`fence_window/accessibility.rs` 将当前有效且成功提交的 ChromeScene、FileScene 和插件语义映射为 `platform::accessibility::Snapshot`。命中与语义继续共享场景几何；UIA 只在发布时将 DIP 裁切区域转换成物理屏幕坐标。节点 ID 保留完整业务身份，插件额外包含实例激活和挂载代次。COM 线程只取得不可变 Arc 数据，不接触 UI RefCell。

原生桥目前提供树导航、名称、类型、屏幕区域和运行时身份；不宣称已有焦点、选择、操作模式或事件。旧节点查询按当前发布身份失效，关闭窗口停止后续发布。非法快照清空导出内容，不沿用旧区域。Windows COM 与跨 apartment 回归已通过；外部 UIA 客户端和屏幕阅读器验收仍待完成，详细证据见 CONTENT_ARCHITECTURE_GOALS.md 第十七轮。

第十八轮新增外部 Windows UIA 验证脚本 `scripts/test-accessibility.ps1`。真实独立客户端已验证文件门户的中文名称、裁切区域、父链/根身份、折叠删除及展开恢复；持有文件引用在折叠后显式查询返回 ElementNotAvailableException。测试使用 debug-only wait-file 屏障与自有实例，当前实机为 96 DPI。操作模式、焦点、事件、插件全路径与屏幕阅读器体验仍待实现/验收。

### 待办稳定身份（第十九轮）

待办配置 v1 以可选迁移字段 `id` / `nextId` 保存任务身份。旧 JSON 在加载时按原顺序补齐，实际写回随正常内容修改发生。撤销保留任务身份且不回退分配器。任务行/checkbox/编辑标题的 SceneNode.id 由任务 ID 与部件种类派生；固定页脚/空状态另用低位身份，避免节点位置或可选控件数量决定身份。行同时成为子控件的语义父节点。

UIA NodeId 已保留场景 u64 的全部位，因此无需另一份业务映射。清除前一条任务后，存活任务场景和 UIA 身份均稳定；action 编号仍沿用原有索引协议，由布局版本验证，不能将动作与稳定元素身份混为一谈。Linux/Windows 回归和外部 UIA 的清除/撤销查询已通过；UIA 发起动作、状态 pattern 和焦点仍待接入。

### 组件身份必须在声明时给出（第二十轮）

WidgetElement 必须带 id/parent；WidgetFrame 只做比例适配及 Scene 构建，不再按节点顺序生成身份，也不提供事后修改身份的入口。固定控件使用固定 ID，动态业务节点使用业务身份派生 ID。日历日期由完整公历日期决定身份，星期由实际星期决定；便笺正文与页脚、时钟不同布局下的时间和日期均显式保留身份。绘制内容与语义名称可以不同：日期显示日号，但语义提供完整日期。

日历跨月焦点清理、星期重排/缩放、便笺撤销和时钟布局回归通过。外部 UIA 验证便笺正文及页脚不会因撤销按钮消失而被重新解释为其他控件；更多模式与真实显示验收仍待完成。

### SPM 字符串业务身份的场景适配（第二十一轮）

SPM 布局通过 PanelView.records 声明完整 RecordId 和 Row/Detail 部件，不让行索引直接成为运行时身份。实例持有 SceneIdentities，将完整键映射到不复用的 u64 SceneNode.id；布局节点、动作索引与运行时身份各有职责。不可见但仍在当前快照内的记录保留映射，已删除记录释放映射内存；旧 ID 不分给新记录。

详情选择保存 RecordId，在当前布局中查索引。重复记录身份在接受来源版本前拒绝；动作仍受来源/布局修订号验证。重排/模式切换/删除和旧动作回归已在 Linux、Windows 原生目标通过，实际外部 SPM 服务和 UIA 操作仍待验收。

### UIA 动作与既有输入共用提交边界（第二十二轮）

UIA Snapshot 的 button 可声明 opaque Invoke token；COM 只读快照并入有界队列，通知失败撤销入队。UI 线程重新核对当前已提交节点、可见几何、生命周期、动作/布局/设备身份后，和键盘/指针共用 invoke_committed → PanelHandle.event → apply_plugin_update。节点身份与动作 token 分开，主题换色不单独取消，旧布局或设备动作拒绝。没有动作的按钮不启用；其他 role 不自动获得 Invoke。

Windows 原生与外部 InvokePattern 已验证便笺撤销及删除按钮后的旧模式引用失效。事件通知、焦点、Toggle/Selection/Value、文件和 chrome 操作仍待实现；不能将单条动作链路视为完整辅助技术支持。
